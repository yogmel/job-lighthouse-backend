# v0.6 Notifications — open items

Decisions and risks from BE-029 (#100) and BE-030 (#101) that need the
owner's call. Nothing here is built.

## Provider choice

- The code uses **Resend** (`common/email.py`).
- `SYSTEM_DESIGN.md` and `CLAUDE.md` still say "not yet chosen". They were
  left unchanged on purpose.
- To switch to Postmark or SES, write one new `*_mailer` function behind the
  `Mailer` type and add its settings.
- **Decide:** keep Resend and update the docs, or switch.

## First digest

- Every job stored before v0.6 has `notified_at = NULL`.
- So the first digest after `RESEND_API_KEY` is set lists **every open job**.
  This follows the design, but the email may be large.
- To skip that backlog, run this once before setting the key:

  ```sql
  UPDATE jobs SET notified_at = now() WHERE notified_at IS NULL;
  ```

- **Decide:** send the backlog or pre-stamp it.

## Silent send failures

- A failed send leaves the run as `success`. The only trace is a WARNING
  log line. No `Runs` or `RunCompanyResult` field shows it.
- A bad key or an unverified `EMAIL_FROM` domain means no digest is ever
  sent, and nothing in `/runs` says so.
- **Before setting the key on the droplet:** do one manual `POST /runs`
  locally with the real key. Check that the email arrives and `notified_at`
  gets filled.
- **Decide:** whether send failures should show up in `/runs` (e.g. a new
  field on `Runs`).

## Slower runs

- The email is sent inline, inside `POST /runs`. It can add up to ~25s
  (the client timeout).
- This adds to the Nginx `proxy_read_timeout` risk from #90.

## No opt-out

- Users can't turn the digest off or unsubscribe.
- Nothing in the schema backs FE-010's Notifications tab yet.
- **Decide:** whether to add a ticket for a per-user setting and an
  unsubscribe link.

## Smaller notes

- **No size cap:** a large backlog goes out as one long email.
- **Not verified against the live Resend API.** Request and response shape
  follow Resend's docs. `EMAIL_FROM` must be on a domain verified in Resend.
